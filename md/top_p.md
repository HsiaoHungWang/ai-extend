# top_p（核取樣，Nucleus Sampling）

**一句話：** 模型只從「累積機率達到 p 的最小候選字集合」裡抽下一個字，其餘全部排除。

## 運作步驟

1. 模型算出所有候選 token 的機率，由高到低排序
2. 從最高的開始往下加，直到累積機率 ≥ top_p 就停
3. 只在這個集合裡重新正規化機率後抽樣

## 例子：「今天天氣很___」

| 候選 | 機率 | 累積 |
|---|---|---|
| 好 | 0.50 | 0.50 |
| 熱 | 0.25 | 0.75 |
| 冷 | 0.15 | 0.90 |
| 悶 | 0.07 | 0.97 |
| 藍 | 0.03 | 1.00 |

- `top_p = 0.5` → 只剩「好」，結果幾乎固定
- `top_p = 0.9` → 從「好、熱、冷」中抽
- `top_p = 1.0` → 全部都可能被抽到（等於不限制）

## 和 temperature 的差別

- **temperature**：改變機率分布的「形狀」（拉尖或壓平）
- **top_p**：決定「哪些字有資格被抽」（剪掉長尾）
- 實務建議：**兩者擇一調整**，另一個維持預設，比較好推論效果

## 常用設定

| 場景 | top_p |
|---|---|
| 程式碼、資料擷取、事實問答 | 0.1–0.5 |
| 一般對話、客服 | 0.8–0.9 |
| 創意寫作、發想 | 0.95–1.0 |

## 呼叫範例（OpenAI 相容格式）

```python
resp = client.chat.completions.create(
    model="...",
    messages=[{"role": "user", "content": "今天天氣很"}],
    top_p=0.9,       # 只從累積機率 90% 的候選字中抽樣
    temperature=1.0  # 維持預設，只調 top_p
)
```

> **教學提醒：** 部分推理型模型會忽略或不接受 top_p，上課示範前建議先確認該模型的 API 文件。
