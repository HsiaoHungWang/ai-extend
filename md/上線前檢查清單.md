# 上線前檢查清單

> 模型推論 API 串接實務｜帶得走的成果 ③
> Demo 跑得動，跟能承接真實流量，中間就差這幾件事。上線前逐項打勾。

## 0. 金鑰與安全

- [ ] API 金鑰不寫死在程式碼裡，改用環境變數或密鑰管理服務
- [ ] `.env` 等含金鑰的檔案已加入 `.gitignore`，沒有推上版控
- [ ] 確認 model 名稱與端點網址正確（避免 404）

## 1. 逾時與重試

- [ ] 自己設定 timeout（例如 60 秒），不用 SDK 預設的 10 分鐘
- [ ] 429、5xx、逾時、連線中斷會自動重試 2～3 次
- [ ] 重試採指數退避（1 秒 → 2 秒 → 4 秒）並加隨機抖動
- [ ] 伺服器回傳 `Retry-After` 時，依指定時間等待
- [ ] 400、401、404 不重試，直接回報錯誤

## 2. 串流回應

- [ ] 給使用者看的長回覆使用 `stream=true`
- [ ] 需要嚴格檢查的回覆（如對外客服）不串流，或檢查完才顯示
- [ ] Agent Loop 的中間步驟不串流，只串流最後的回答

## 3. 成本護欄

- [ ] 每個工作階段設定 token 上限
- [ ] 送出前先估算 token，超過就停止並提示使用者（例如「建議開新對話」）
- [ ] Agent Loop 設定最大步數，避免迴圈把預算燒光
- [ ] 多輪對話已套用記憶策略（滑動視窗或摘要壓縮）控制輸入長度

## 4. 可觀測性

- [ ] 每次呼叫都記錄 `id`、`model`、`tokens`、耗時、`finish_reason`
- [ ] 成功和失敗的呼叫都有記錄
- [ ] 能用 `finish_reason=length` 抓出被截斷的回覆
- [ ] 已針對失敗率與 P95 耗時設定告警
- [ ] 日誌以統計資訊為主，提示詞與回覆內容遮罩個資後才存

## 5. 輸入輸出防護

- [ ] 輸入端會擋下常見的提示詞注入（如「忽略之前的指示」）
- [ ] 個資送進模型前先遮罩
- [ ] 輸出顯示前檢查格式、必要欄位與禁用字詞
- [ ] 格式不符時，會帶著錯誤訊息請模型重寫一次
- [ ] 工具權限最小化，敏感動作需人工確認

## 6. 可重複的評測

- [ ] 準備 20～50 題固定測試集，涵蓋常見與邊界案例
- [ ] 每次改提示詞或換模型後，先跑一次測試集再上線
- [ ] 保留每次評測結果，能比較改版前後的差異
